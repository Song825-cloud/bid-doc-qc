# 投标技术文件质检流程（通用模板）

> 标准流程：**唯一入口 `python qc/run.py`**
> 交付物：`投标文件/技术文件质检报告（问题清单版）YYYYMMDD.docx`
>
> 本模板来自一次抽水蓄能项目投标质检的实践总结，**具体数据须按新项目重建**。

---

## 零、新手三步

**第 1 步：双击 `qc/run.cmd`**（不会命令行就双击，菜单选 `1`）
> 等价命令：`python qc/run.py`，几秒跑完，屏幕出现「全部断言通过」即成功。

**第 2 步：打开报告**
> `投标文件/技术文件质检报告（问题清单版）YYYYMMDD.docx`
> 阅读顺序：**封面「一页看懂」→ 第二章问题清单 → 附录一/二**。
> 第三章之后的招标基准、评分点、专项取证、形式要件是备查，不必逐条读。

**第 3 步：照着改**
> 问题清单每行就是一件事：问题是什么、在哪个页（出现位置列可直接翻页）、
> 招标文件怎么要求的（招标依据页码列）、建议怎么改（处理建议列）。
> P0 与 P1 须在投标截止前改完。

### 什么时候需要跑别的模式

| 情况 | 跑什么 |
|---|---|
| 日常确认报告是最新的 | 选 `1`（快速） |
| 技术文件改版了、页码可能漂移 | 选 `2`（重取页码） |
| 换了新项目 / 结论数据大改 | 选 `3`（全流程） |
| 需要完整取证底册 | 选 `4` |

### 跑失败了怎么办

屏幕会打印 `!!! 阶段失败：xxx` 和退出码。最常见两种：
1. **文件被占用** → 报告正被 Word/预览打开，关掉再跑（脚本已自动写临时文件兜底）
2. **断言 FAIL** → 会列出哪一条不符合，说明 `data_rc.py` 或 `check_slim.py` 的期望值没同步改

## 一、这个流程做什么

对投标技术文件（施工组织设计）做**四重质检 + 三项专项核查**，产出「问题清单版」报告：

| 阶段 | 做什么 | 脚本 |
|---|---|---|
| **1 解析** | docx → 带章节路径的结构化文本（一次性） | `parse_bid.py` |
| **2 扫描** | 按维度规则扫描：错字/工期/机构/范围/规范/澄清/专项 | `scan_*.py` |
| **3 定位** | 每个检查项定位到投标文件页码 + 招标文件页码 | `tender_pages2.py`、`bid_pages_all.py` |
| **4 渲染** | 生成问题清单版报告 | `build_slim.py` |
| **5 断言** | 18 条回归断言，任一不过即失败 | `check_slim.py` |

---

## 二、一条命令

```bash
python qc/run.py                # 快速：重建报告 + 断言 —— 日常用这个
python qc/run.py --locate       # 技术文件改版后重跑页码
python qc/run.py --all          # 全流程重跑
python qc/run.py --full-report  # 额外产出完整版（取证底册）
```

**任一阶段失败立即中止并返回非 0**，不会产出半成品。

```
│   └─ 技术文件四重质检报告（含页码版）YYYYMMDD.docx ← 完整版取证底册（按需）
├─ output/
│   └─ overview.md                交付说明
└─ qc/
    ├─ run.py                 ← 唯一入口
    ├─ README.md              ← 本文件
    ├─ check_slim.py          ← 回归断言
    ├─ parse_bid.py           阶段1
    ├─ scan_*.py              阶段2
    ├─ tender_pages2.py       阶段3a 招标页码
    ├─ bid_pages_all.py       阶段3b 投标页码
    ├─ data_s1/s3/s4.py       各维度结论数据（按项目重建）
    ├─ data_rc.py             问题清单数据（按项目重建）
    ├─ page_map.py            页码映射中枢
    ├─ gen_report.py          渲染引擎（样式/表格）
    ├─ build_slim.py          阶段4 问题清单版
    ├─ toc.json               页码口径配置（单点定义）
    └─ 归档子目录             一次性脚本与日志（不再维护，不随技能包分发）
```

## 四、阶段详解

### 阶段 1 解析
`parse_bid.py` 把 docx 按文档流顺序解析为带章节路径的结构化文本
（`bid_struct.txt` / `.json`）。下游全部依赖它，**只解析一次**。
技术文件改版后必须重跑。

### 阶段 2 扫描
各脚本各管一个维度，产出 `*.json` 原始命中，供人工归因成结论：

| 脚本 | 维度 | 输出 |
|---|---|---|
| `scan_a_typo.py` | 第一重项目名一致性 + 第四重错字格式 | `typos.json` |
| `scan_b.py` | B 组 工期/日期/里程碑 | `b_hits.json` |
| `scan_cde.py` | C/D/E 组 机构/设备/平面 | — |
| `scan_g.py` | G 组 工程范围与模板串用 | `g_hits.json` |
| `scan_f2.py` | F 组 标准规范版本 | `f_stds.json`、`f_conflicts.json` |
| `scan_clarify.py` | 答疑澄清条款落实核查 | — |
| `scan_spot.py` | 三项专项（工期/设备/工程量） | `spot_raw.json` |

> 扫描只负责「找到原始命中」，**不下结论**。结论由 `data_s*.py` / `data_rc.py` 人工归因后写入。

### 阶段 3 定位（口径单点定义）
- `tender_pages2.py`：招标/答疑/施工图 PDF 按页拆分后关键词定位
- `bid_pages_all.py`：用 Word COM 打开 docx，`Repaginate` 后取 `Information(3)` 页码
- **页码口径只写在 `toc.json` 一个地方**：`toc_end` 为封面/目录截止页
- ⚠️ 本模板示例项目实测**无封面页与目录页**（`toc_end = 0`）。换项目时**必须先实测再定阈值**（用 `scripts/pages_head.py` 打印每页首段判断），否则会丢正文页码

### 阶段 4 渲染
`build_slim.py` 单入口，产出问题清单版。**不按审查视角分章，按「问题」组织。**

### 阶段 5 断言
`check_slim.py` 18 条断言，覆盖：表数、节数、问题条数与等级分布、页码空值、
附录条数、列数回归（防止责任人/时限/状态/复核人列回来）、禁用语（「根因」等）、页脚页码域。

## 五、固定下来的约定

### 报告结构（问题清单版，8 张表）
| 表 | 内容 |
|---|---|
| 1 | 等级图例与统计 |
| 2 | **问题清单** |
| 3 | 关键招标基准 |
| 4 | 技术评分点响应与失分风险 |
| 5 | 专项核查关键取证 |
| 6 | 报送前形式要件自查 |
| 附录一 | 已核查且合规 |
| 附录二 | 待补充材料 |

### 计级规则
- **一问题一记**：同一问题只出现一次，全部出现位置并入同一行的「出现位置」列
- 「通过」与「待核验」不进正文，下沉附录
- 问题清单列固定为 **7 列**：编号 / 问题 / 等级 / 原条目 / 出现位置（投标页码）/ 招标依据页码 / 处理建议
- **不列**责任人、完成时限、状态、复核人

### 表述规范
- 用**正常查找口径**直述问题：什么错、错在哪、应该是什么
- **禁用抽象管理术语**：根因、闭环、抓手、顶层设计等
- 等级：P0 致命（否决/必扣分）｜P1 严重（影响评分点）｜P2 一般（规范格式）

### 命名规范
- 交付物：`技术文件质检报告（问题清单版）YYYYMMDD.docx`
- 中间数据：`*.json` / `*.txt` 不删，供追溯
- 一次性脚本与日志：_archive 目录

## 六、换一个项目怎么做

**可直接复制**（改配置即可）：
`parse_bid.py`、`scan_*.py`、`bid_pages_all.py`、`tender_pages2.py`、
`page_map.py`、`gen_report.py`、`build_slim.py`、`check_slim.py`、`run.py`

**必须按项目重建**：
| 文件 | 要改什么 |
|---|---|
| `toc.json` | 先实测封面/目录页范围，再定 `toc_end` |
| `data_s1.py` / `data_s3.py` / `data_s4.py` | 检查项、招标基准、等级、处理建议 |
| `data_rc.py` | 问题清单（编号、问题、等级、原条目、页码成员、招标依据、建议） |
| `check_slim.py` 的 `EXP` | 期望条数与等级分布 |
| 各 `scan_*.py` 的数据表 | 关键词、地名、里程碑、他项目名等 |
| 招标/答疑 PDF | 放入 `招标文件/`，解析文本按 正文/答疑/图纸 命名 |

## 七、已知坑与对策

| 坑 | 对策 |
|---|---|
| Word 打开大体积文档，`Repaginate` 需数十秒至十余分钟 | 阶段 3 单独跑（`--locate`），不要每次重建都跑 |
| `doc.save()` 报 PermissionError | 文件被预览/Word 占用。先写 `_tmp.docx` 再 `copy2` 落最终名 |
| Word Find 对部分长句/含数字串 0 命中 | 每项准备 2–4 个候选词（从短到长），全部失败则该项留空并在报告标注 |
| docx 无固定分页，调整字体/页边距后页码整体漂移 | 报告附录写明口径；改版后跑 `--locate` 重取 |
| 报告被反复覆盖后无法分辨版本 | 文件名带日期；`data_rc.py` 变更即视为新版本 |
