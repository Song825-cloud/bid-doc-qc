# 踩坑与口径（投标质检流程）

> 以下来自一次抽水蓄能项目质检的实测总结，换项目时**先读这份再动手**，但具体阈值须重新实测。

## 一、docx 页码定位（Word COM）

### 1.1 必须先验证有没有目录页（最容易踩的坑）
若按「前 N 页是目录/封面」想当然过滤页码，可能把正文首页也滤掉，导致第 1 章正文页码
整体丢失，且不同维度**口径不一致**（一个过滤、一个不过滤）。

**做法**：用 `scripts/pages_head.py` 打印前若干页每页的首个段落，人工确认正文起点，
再把 `toc_end` 写进 `qc/toc.json`。

### 1.2 Word Find 对部分串 0 命中
同一段落内，有些短语能命中，含数字的长句却常 0 命中。

**做法**：每项准备 **2—4 个候选关键词，从短到长**依次尝试，取第一个有结果的；
全部失败则该项页码留空，报告中标注「未能定位」。

### 1.3 逐段遍历比 Find 更可靠
`for i in 1..Paragraphs.Count` 取 `p.Range.Text` 做 Python 侧 `in` 判断，
命中才取 `p.Range.Information(3)`。数万段全遍历约数十秒到一两分钟（不是 O(n²)，可放心用）。
需要精确到段时优先用这个（参考 `scripts/bid_pages_all.py`）。

### 1.4 必须先开 Pagination
```python
app.Options.Pagination = True      # 不开则 Information(3) 恒返回 1
doc.Repaginate()                   # 大体积文档需数十秒至十余分钟
doc.ComputeStatistics(2)           # 总页数
```
逐项搜索时**每项都要重置 `rng = doc.Content`**，并设 `f.Wrap = 0`（wdFindStop），
否则会从上一次命中位置继续而漏命中。

## 二、Windows 环境

### 2.1 doc.save() 报 PermissionError
报告正被 Word/预览面板占用。**做法**：先写 `<名>_tmp.docx`，再 `shutil.copy2` 到最终名；
仍被占用则降级为 `…V2` 名并提示用户，不要反复重试。

### 2.2 .cmd 启动器不能写中文
Windows 批处理写中文会乱码，且乱码行会被当命令执行。
**做法**：`run.cmd` 内容保持纯 ASCII（菜单用英文），中文说明放 README。

### 2.3 结束 Word 进程
```bash
taskkill //F //IM WINWORD.EXE      # Git Bash 下必须双斜杠
```

### 2.4 Python 解释器
建议用隔离环境（如 WorkBuddy 内置 Python），不要混用系统 Python。
依赖：`python-docx`、`pywin32`、`pymupdf`。

## 三、PDF 页码定位

- 解析文本按页插入 `===== [文件名] 第N页 =====` 标记，按标记 split 后关键词 norm 化匹配
- **目录页含大量连续点线**（`\.{4,}`），提取章节名时必须排除，否则章节名会污染所有页
- 有些词在招标文件里**根本不存在**。此类项不要硬凑，改指招标范围页或合同条款页，并说明依据

## 四、口径单点定义

页码阈值、受检文件、PDF 列表**只在一处定义**：
- 阈值 → `qc/toc.json`
- 受检 docx → `_paths.find_bid_docx()`（取 `投标文件/` 下最大的非报告 docx）
- PDF → `_paths.find_tender_txts()`（按文件名关键词识别 正文/答疑/图纸）

多套实现并存是缺陷的根源——曾因两套页码脚本阈值不同，
导致同一问题在一张表里有页码、另一张表里为空。

## 五、报告被占用/版本混淆

- 文件名带日期（`…YYYYMMDD.docx`），改结论数据即视为新版本
- 一次性脚本与日志及时移入 qc 下的 _archive 目录，避免下次误用旧结论
